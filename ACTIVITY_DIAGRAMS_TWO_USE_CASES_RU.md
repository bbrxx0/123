# Диаграммы деятельности для двух простых use cases системы StayFinder

## Описание
Этот документ содержит подробные инструкции для создания двух простых диаграмм деятельности (Activity Diagrams) в Visual Paradigm Community Edition для системы бронирования отелей StayFinder.

Выбраны два самых простых варианта использования:
1. **Вход в систему (User Login)** - простой процесс аутентификации
2. **Поиск отелей (Search Hotels)** - базовый процесс поиска

---

## Use Case 1: Вход в систему (User Login)

### Описание процесса
Пользователь вводит свои учетные данные (email и пароль) для входа в систему. Система проверяет данные и либо предоставляет доступ, либо отклоняет запрос.

### Активности (всего 8):

1. **Начало (Start)** - начальный узел
2. **Открыть страницу входа** - пользователь переходит на /auth/login
3. **Ввести email** - пользователь вводит свой email в форму
4. **Ввести пароль** - пользователь вводит пароль
5. **Нажать кнопку "Войти"** - отправка формы
6. **Проверить учетные данные** - система проверяет email и пароль в базе данных
7. **Decision: Данные верны?** - узел решения
   - **[Нет]** → **Показать ошибку "Неверный email или пароль"** → возврат к вводу данных
   - **[Да]** → продолжение
8. **Decision: Email подтвержден?** - проверка is_email_confirmed
   - **[Нет]** → **Показать сообщение "Подтвердите email"** → End
   - **[Да]** → продолжение
9. **Создать сессию пользователя** - система вызывает login_user()
10. **Перенаправить на главную страницу** - redirect to index или next URL
11. **Конец (End)** - конечный узел

### Пошаговая инструкция для Visual Paradigm:

#### Шаг 1: Создание новой диаграммы
1. Откройте Visual Paradigm Community Edition
2. Выберите: **Diagram → New → Activity Diagram**
3. Название: **"Use Case 1 - User Login"**
4. Нажмите **OK**

#### Шаг 2: Добавление Swimlanes (дорожек)
1. Правый клик на диаграмме → **Insert → Swimlane → Vertical**
2. Создайте 2 дорожки:
   - **"Пользователь"** (User) - слева
   - **"Система"** (System) - справа
3. Настройте ширину дорожек, перетаскивая границу между ними

#### Шаг 3: Добавление элементов в дорожку "Пользователь"

1. **Начальный узел:**
   - Выберите инструмент **"Initial Node"** (черный круг)
   - Кликните в верхней части дорожки "Пользователь"

2. **Активность "Открыть страницу входа":**
   - Выберите **"Action"** (прямоугольник со скругленными углами)
   - Кликните под начальным узлом
   - Введите текст: **"Открыть страницу входа"**

3. **Соединение:**
   - Выберите **"Control Flow"** (стрелка)
   - Соедините начальный узел с активностью

4. **Добавьте следующие активности:**
   - **"Ввести email"**
   - **"Ввести пароль"**
   - **"Нажать кнопку Войти"**
   
   Соединяйте каждую активность стрелкой с предыдущей.

#### Шаг 4: Добавление элементов в дорожку "Система"

1. **Активность "Проверить учетные данные":**
   - Создайте Action в дорожке "Система"
   - Текст: **"Проверить учетные данные в БД"**
   - Соедините стрелкой от "Нажать кнопку Войти" (из дорожки пользователя)

2. **Decision Node "Данные верны?":**
   - Выберите **"Decision Node"** (ромб)
   - Поместите под "Проверить учетные данные"
   - Соедините стрелкой
   
3. **Ветка "НЕТ" (ошибка):**
   - От Decision Node проведите стрелку влево
   - На стрелке добавьте условие: **"[Нет]"**
   - Создайте Action: **"Показать ошибку 'Неверный email или пароль'"**
   - От этой активности проведите стрелку обратно к "Ввести email" (используйте точки изгиба для красивого маршрута)

4. **Ветка "ДА" (успешно):**
   - От Decision Node проведите стрелку вниз
   - На стрелке: **"[Да]"**
   - Создайте второй Decision Node: **"Email подтвержден?"**

5. **Проверка подтверждения email:**
   - От "Email подтвержден?" две ветки:
     - **[Нет]** → Action: **"Показать сообщение 'Подтвердите email'"** → Activity Final Node
     - **[Да]** → продолжение

6. **Успешный вход:**
   - Action: **"Создать сессию пользователя (login_user)"**
   - Action: **"Перенаправить на главную страницу"**
   - **Activity Final Node** (круг с точкой внутри)

#### Шаг 5: Оформление

1. **Добавьте подписи на стрелках от Decision Nodes:**
   - Дважды кликните на стрелку
   - В поле "Guard" введите условие: [Да] или [Нет]

2. **Выровняйте элементы:**
   - Выделите несколько элементов
   - Правый клик → **Align → Align Center**

3. **Настройте цвета (опционально):**
   - Активности пользователя: светло-голубой
   - Активности системы: светло-зеленый
   - Decision nodes: желтый

4. **Добавьте примечание (Note):**
   - Выберите инструмент **"Note"**
   - Разместите в углу диаграммы
   - Текст: **"Use Case: Вход в систему. Актеры: Пользователь, Система"**

#### Шаг 6: Сохранение
1. **File → Save** или **Ctrl+S**
2. Экспорт: **File → Export → Export Diagrams As Images**
3. Выберите формат PNG или PDF

## Use Case 2: Поиск отелей (Search Hotels)

### Описание процесса
Пользователь (авторизованный или гость) ищет отели по названию или городу. Система фильтрует и отображает результаты поиска.

### Активности (всего 9):

1. **Начало (Start)** - начальный узел
2. **Открыть главную страницу** - пользователь на странице "/"
3. **Просмотр всех отелей** - система показывает все отели по умолчанию
4. **Decision: Использовать фильтр?** - пользователь решает
   - **[Нет]** → переход к "Просмотр результатов"
   - **[Да]** → ввод критериев поиска
5. **Ввести название отеля (опционально)** - пользователь вводит текст в поле поиска
6. **Выбрать город (опционально)** - пользователь выбирает город из списка или вводит
7. **Нажать кнопку "Найти"** - отправка формы поиска
8. **Применить фильтры** - система фильтрует отели по критериям (query.filter)
9. **Decision: Найдены результаты?** - проверка
   - **[Нет]** → **Показать сообщение "Отели не найдены"**
   - **[Да]** → продолжение
10. **Отобразить список отелей** - показ карточек отелей с фото, названием, городом, звездами
11. **Выбрать отель для просмотра (опционально)** - клик на карточку отеля
12. **Конец (End)** - конечный узел

### Пошаговая инструкция для Visual Paradigm:

#### Шаг 1: Создание диаграммы
1. **Diagram → New → Activity Diagram**
2. Название: **"Use Case 2 - Search Hotels"**
3. **OK**

#### Шаг 2: Добавление Swimlanes
1. Правый клик → **Insert → Swimlane → Vertical**
2. Создайте 2 дорожки:
   - **"Пользователь"** (User/Guest)
   - **"Система"** (System)

#### Шаг 3: Создание основного потока

**В дорожке "Пользователь":**

1. **Initial Node** (черный круг) - в верхней части
2. **Action:** "Открыть главную страницу (/)"
3. Соедините стрелкой

**В дорожке "Система":**

4. **Action:** "Показать все отели (по умолчанию)"
5. Соедините стрелкой от предыдущей активности

**Обратно в дорожке "Пользователь":**

6. **Decision Node:** "Использовать поиск?"
   - Разместите под "Показать все отели"
   - Соедините стрелкой

7. **Ветка [Нет]:**
   - Стрелка с условием **"[Нет, просто просмотр]"**
   - Ведет напрямую к "Просмотр списка отелей" (создадим позже)

8. **Ветка [Да]:**
   - Стрелка с условием **"[Да, применить фильтры]"**
   - Action: **"Ввести название отеля"**
   - Action: **"Ввести город"**
   - Action: **"Нажать кнопку Найти"**
   - Соединяйте последовательно

#### Шаг 4: Обработка поиска в системе

**В дорожке "Система":**

1. **Action:** "Применить фильтры к базе данных"
   - Соедините от "Нажать кнопку Найти"

2. **Action:** "Выполнить SQL-запрос с условиями LIKE"
   - Под предыдущей активностью

3. **Decision Node:** "Найдены отели?"
   - Разместите под запросом

4. **Ветка [Нет]:**
   - Стрелка **"[Нет, 0 результатов]"**
   - Action: **"Показать сообщение 'Отели не найдены'"**
   - Merge обратно к основному потоку или к End

5. **Ветка [Да]:**
   - Стрелка **"[Да, есть результаты]"**
   - Action: **"Отобразить список отелей с карточками"**

#### Шаг 5: Объединение потоков

1. **Merge Node (ромб):**
   - Разместите там, где сходятся ветки:
     - От "Использовать поиск? [Нет]"
     - От "Отобразить список отелей"
   - Это точка объединения для просмотра результатов

**В дорожке "Пользователь":**

2. **Action:** "Просмотр результатов поиска"
3. **Decision Node:** "Выбрать отель?"
   - **[Нет]** → Activity Final Node (конец)
   - **[Да]** → Action: "Кликнуть на карточку отеля" → End

#### Шаг 6: Альтернативный поток - без результатов

Если отели не найдены:
1. От "Показать сообщение 'Отели не найдены'"
2. Соедините с **Activity Final Node**

#### Шаг 7: Оформление диаграммы

1. **Расположение элементов:**
   - Основной поток - по центру, сверху вниз
   - Альтернативные ветки - справа или слева от основного потока

2. **Подписи на переходах:**
   - Все Decision Nodes должны иметь подписи на стрелках
   - Используйте квадратные скобки: [Да], [Нет]

3. **Цветовое кодирование:**
   - Активности ввода данных (пользователь): голубой
   - Активности обработки данных (система): зеленый
   - Decision nodes: оранжевый или желтый

4. **Примечания:**
   - Добавьте Note: **"Use Case: Поиск отелей"**
   - Укажите: **"Поддерживает поиск по названию и городу"**
   - **"Параметры: ?q={query}&city={city}"**

5. **Выравнивание:**
   - Выделите все элементы в дорожке
   - Align → Align Center (по горизонтали)

#### Шаг 8: Проверка и сохранение

1. **Проверьте:**
   - Все стрелки имеют направление
   - Есть хотя бы один путь от Start до End
   - Decision Nodes имеют минимум 2 выхода
   - Все условия подписаны

2. **Сохранение:**
   - **File → Save** (Ctrl+S)
   - **File → Export → Export Diagrams As Images**
   - Выберите PNG (для вставки в документы) или PDF (для печати)

## Краткая шпаргалка по элементам Activity Diagram

| Элемент | Иконка | Использование |
|---------|---------|---------------|
| **Initial Node** | ⚫ Черный круг | Начало процесса (один на диаграмму) |
| **Activity Final Node** | ⊗ Круг с точкой | Конец процесса (может быть несколько) |
| **Action** | ▭ Скругленный прямоугольник | Отдельная активность/действие |
| **Decision Node** | ◇ Ромб | Точка ветвления (if/else) |
| **Merge Node** | ◇ Ромб | Точка слияния потоков |
| **Control Flow** | → Стрелка | Переход между активностями |
| **Fork Node** | ▬ Жирная линия | Разделение на параллельные потоки |
| **Join Node** | ▬ Жирная линия | Синхронизация параллельных потоков |
| **Swimlane** | \|\| Вертикальные полосы | Разделение по ролям/актерам |
| **Note** | 📄 Листок с загнутым углом | Комментарии и пояснения |

## Сравнение двух use cases

| Параметр | Use Case 1: Login | Use Case 2: Search Hotels |
|----------|-------------------|---------------------------|
| **Сложность** | Очень простая | Простая |
| **Количество активностей** | 8-10 | 9-12 |
| **Количество Decision Nodes** | 2 | 2 |
| **Количество дорожек** | 2 (User, System) | 2 (User, System) |
| **Альтернативные потоки** | 2 (неверные данные, не подтвержден email) | 2 (без фильтра, нет результатов) |
| **Время создания** | ~10-15 минут | ~15-20 минут |
| **Актеры** | Пользователь, Система | Пользователь/Гость, Система |
| **Предусловие** | Пользователь зарегистрирован | Нет (доступно всем) |
| **Постусловие** | Пользователь авторизован | Отображен список отелей |

## Дополнительные советы для быстрого создания

### Общие рекомендации:
1. **Начните с Swimlanes** - это упростит организацию
2. **Создавайте элементы сверху вниз** - естественный поток чтения
3. **Используйте копирование** (Ctrl+C, Ctrl+V) для похожих элементов
4. **Горячие клавиши:**
   - `A` - Action
   - `D` - Decision Node
   - `C` - Control Flow
   - `Ctrl+S` - Сохранить
   - `Ctrl+Z` - Отмена

### Для экономии времени:
1. **Не перфекционизм:** Не нужно идеально выравнивать каждый элемент
2. **Базовое оформление:** Можно не использовать цвета (черно-белая диаграмма тоже подходит)
3. **Минимум примечаний:** Достаточно названия диаграммы
4. **Прямые линии:** Не усложняйте маршруты стрелок

### Типичные ошибки, которых надо избегать:
❌ Забыть подписать условия на Decision Node  
❌ Создать Decision Node только с одним выходом  
❌ Не соединить все элементы стрелками  
❌ Забыть добавить Initial Node или Final Node  
❌ Пересекающиеся стрелки (используйте точки изгиба)
