# Инструкция по созданию диаграмм UML для системы StayFinder в Visual Paradigm Community Edition

## Описание системы
StayFinder - это веб-приложение для бронирования отелей, разработанное на Flask (Python). Система включает в себя функционал регистрации пользователей, поиска отелей, бронирования номеров, онлайн-платежей через Stripe и административную панель.

### Отношения между классами:

1. **User → Reservation** (один ко многим)
   - User имеет множество Reservation
   - Связь: 1..* (один пользователь - много бронирований)

2. **Room → Reservation** (один ко многим)
   - Room имеет множество Reservation
   - Связь: 1..* (один номер - много бронирований)

3. **Hotel → Room** (один ко многим)
   - Hotel имеет множество Room
   - Связь: 1..* (один отель - много номеров)

4. **AuthService → User** (зависимость/использование)
   - AuthService создает и управляет User
   - Стрелка зависимости (пунктирная линия)

5. **AuthService → SecurityService** (зависимость)
   - AuthService использует SecurityService для токенов
   - Стрелка зависимости

6. **AuthService → EmailService** (зависимость)
   - AuthService использует EmailService для отправки писем
   - Стрелка зависимости

7. **BookingService → Room** (зависимость)
   - BookingService работает с Room
   - Стрелка зависимости

8. **BookingService → Reservation** (зависимость)
   - BookingService создает Reservation
   - Стрелка зависимости

9. **PaymentService → Reservation** (зависимость)
   - PaymentService обновляет статус платежа в Reservation
   - Стрелка зависимости

10. **PaymentService → EmailService** (зависимость)
    - PaymentService использует EmailService для отправки чеков
    - Стрелка зависимости

11. **AdminService → Hotel** (зависимость)
    - AdminService управляет Hotel
    - Стрелка зависимости

12. **AdminService → Room** (зависимость)
    - AdminService управляет Room
    - Стрелка зависимости

13. **AdminService → Reservation** (зависимость)
    - AdminService управляет Reservation
    - Стрелка зависимости

14. **Все сервисы → DatabaseContext** (зависимость)
    - Все сервисы используют DatabaseContext для работы с БД
    - Стрелки зависимости

### Пошаговая инструкция для Visual Paradigm:

#### Шаг 1: Создание нового проекта
1. Откройте Visual Paradigm Community Edition
2. Нажмите File → New → Project
3. Введите название проекта: "StayFinder Hotel Booking System"
4. Нажмите OK

#### Шаг 2: Создание диаграммы классов
1. В главном меню выберите: Diagram → New
2. Выберите "Class Diagram"
3. Введите название: "StayFinder Class Diagram"
4. Нажмите OK

#### Шаг 3: Добавление классов моделей данных
1. На панели инструментов слева найдите иконку "Class"
2. Кликните на холсте, чтобы создать класс
3. Введите имя: "User"
4. Дважды кликните на класс, чтобы открыть окно свойств
5. Перейдите на вкладку "Attributes"
6. Добавьте все атрибуты из списка выше (кнопка "+"):
   - id: int
   - email: String
   - password_hash: String
   - и т.д.
7. Перейдите на вкладку "Operations" (методы)
8. Добавьте методы (кнопка "+"):
   - set_password(password: String): void
   - check_password(password: String): Boolean
   - confirm_email(): void
9. Нажмите OK

#### Шаг 4: Повторите процесс для остальных классов
Создайте следующие классы в таком же порядке:
- Hotel (справа от User)
- Room (под Hotel)
- Reservation (между User и Room)

#### Шаг 5: Добавление классов-сервисов
Создайте сервисные классы (расположите их ниже основных моделей):
- AuthService
- SecurityService
- EmailService
- PaymentService
- BookingService
- AdminService
- DatabaseContext

Для сервисов можно добавить стереотип <<Service>>:
1. Дважды кликните на класс
2. В поле "Stereotype" выберите "Service" или введите вручную
3. Нажмите OK

#### Шаг 6: Создание ассоциаций (связей)
1. На панели инструментов выберите "Association" (линия со стрелками)
2. Кликните на User, затем на Reservation
3. Дважды кликните на линию связи
4. На стороне User установите множественность: 1
5. На стороне Reservation установите множественность: *
6. Добавьте имя роли на стороне Reservation: "reservations"
7. Нажмите OK

Повторите для других ассоциаций:
- Hotel (1) → Room (*)
- Room (1) → Reservation (*)

#### Шаг 7: Создание зависимостей
1. На панели инструментов выберите "Dependency" (пунктирная стрелка)
2. Соедините классы согласно списку отношений выше
3. Для каждой зависимости можно добавить метку (например, "uses", "creates")

Основные зависимости:
- AuthService → User, SecurityService, EmailService
- BookingService → Room, Reservation
- PaymentService → Reservation, EmailService
- AdminService → Hotel, Room, Reservation
- Все сервисы → DatabaseContext

#### Шаг 8: Настройка визуального представления
1. Расположите классы логично:
   - Модели данных (User, Hotel, Room, Reservation) - в верхней части
   - Сервисы - в средней/нижней части
   - DatabaseContext - в самом низу, по центру
2. Выровняйте классы: выделите несколько классов → правый клик → Align → Align Left/Center/Right
3. Отформатируйте линии связей: кликните на линию → перетащите точки для изменения маршрута

#### Шаг 9: Добавление пакетов (опционально)
Для лучшей организации можно сгруппировать классы в пакеты:
1. Выберите инструмент "Package" на панели
2. Создайте пакеты:
   - "models" (для User, Hotel, Room, Reservation)
   - "services" (для всех сервисных классов)
   - "infrastructure" (для DatabaseContext)
3. Перетащите классы в соответствующие пакеты

#### Шаг 10: Сохранение диаграммы
1. File → Save
2. Или Ctrl+S

## Часть 2: Диаграмма активности (Activity Diagram)

### Процесс: "Бронирование номера в отеле с оплатой"

Этот процесс охватывает полный цикл от поиска отеля до подтверждения бронирования с оплатой.

### Активности (минимум 10):

1. **Начало** (Start) - начальный узел
2. **Поиск отеля** - пользователь вводит критерии поиска (город, название)
3. **Отображение списка отелей** - система показывает результаты поиска
4. **Выбор отеля** - пользователь выбирает отель из списка
5. **Просмотр деталей отеля** - система показывает информацию об отеле и доступных номерах
6. **Выбор номера** - пользователь выбирает подходящий номер
7. **Проверка авторизации** - Decision node: пользователь авторизован?
   - Если НЕТ → **Перенаправление на страницу входа/регистрации**
   - Если ДА → продолжение
8. **Вход/Регистрация пользователя** (если не авторизован)
   - Ввод email и пароля
   - Подтверждение email (отправка письма)
   - Переход обратно к бронированию
9. **Ввод дат бронирования** - пользователь указывает даты заезда и выезда
10. **Проверка доступности номера** - система проверяет, свободен ли номер на выбранные даты
    - Decision node: Номер доступен?
    - Если НЕТ → **Отображение сообщения об ошибке** → возврат к вводу дат
    - Если ДА → продолжение
11. **Создание бронирования** - система создает запись Reservation со статусом "pending"
12. **Расчет общей стоимости** - система вычисляет total_price (количество ночей × цена за ночь)
13. **Инициация процесса оплаты** - переход к интеграции со Stripe
14. **Создание Stripe Checkout Session** - система создает сессию оплаты в Stripe
15. **Перенаправление на Stripe** - пользователь перенаправляется на страницу оплаты Stripe
16. **Ввод платежных данных** - пользователь вводит данные карты на странице Stripe
17. **Обработка платежа** - Stripe обрабатывает транзакцию
    - Decision node: Оплата успешна?
    - Если НЕТ → **Отображение ошибки оплаты** → возврат к списку бронирований
    - Если ДА → продолжение
18. **Обновление статуса платежа** - система обновляет payment_status на "paid"
19. **Обновление статуса бронирования** - система обновляет status на "confirmed"
20. **Отправка чека на email** - система отправляет письмо с подтверждением и чеком
21. **Логирование события** - запись в admin.log о успешной оплате
22. **Отображение страницы успеха** - показ страницы с подтверждением бронирования
23. **Конец** (End) - конечный узел

### Дополнительные потоки:

**Альтернативный поток: Отмена бронирования**
- Пользователь переходит в "Мои бронирования"
- Выбирает бронирование
- Нажимает "Отменить"
- Система обновляет status на "canceled"
- Показ сообщения об успешной отмене

### Пошаговая инструкция для создания диаграммы активности:

#### Шаг 1: Создание новой диаграммы активности
1. В главном меню Visual Paradigm выберите: Diagram → New
2. Выберите "Activity Diagram"
3. Введите название: "Hotel Room Booking with Payment Process"
4. Нажмите OK

#### Шаг 2: Добавление начального узла
1. На панели инструментов слева найдите "Initial Node" (черный круг)
2. Кликните на холсте в верхней части
3. Это будет стартовая точка процесса

#### Шаг 3: Добавление первой активности
1. Выберите инструмент "Action" (прямоугольник со скругленными углами)
2. Кликните под начальным узлом
3. Введите название: "Поиск отеля"
4. Нажмите Enter

#### Шаг 4: Соединение узлов
1. Выберите инструмент "Control Flow" (стрелка)
2. Кликните на начальный узел, затем на активность "Поиск отеля"
3. Стрелка соединит их

#### Шаг 5: Добавление следующих активностей
Продолжайте добавлять активности в следующем порядке (каждую под предыдущей):
1. "Отображение списка отелей"
2. "Выбор отеля"
3. "Просмотр деталей отеля"
4. "Выбор номера"

Соединяйте каждую активность стрелкой Control Flow с предыдущей.

#### Шаг 6: Добавление узла решения (Decision Node)
1. Выберите инструмент "Decision Node" (ромб)
2. Поместите его под "Выбор номера"
3. Подпишите: "Пользователь авторизован?"
4. От decision node будет две стрелки:
   - Одна с подписью "[Нет]" → ведет к "Вход/Регистрация"
   - Одна с подписью "[Да]" → ведет к "Ввод дат бронирования"

#### Шаг 7: Добавление ветки авторизации
1. Справа от decision node создайте активность "Вход/Регистрация пользователя"
2. Под ней: "Отправка email подтверждения"
3. Под ней: "Подтверждение email"
4. Затем стрелкой соедините обратно к основному потоку (к "Ввод дат бронирования")

Для возврата используйте инструмент "Merge Node" (ромб) для объединения потоков.

#### Шаг 8: Продолжение основного потока
Продолжайте добавлять активности:
1. "Ввод дат бронирования"
2. "Проверка доступности номера"
3. Decision Node: "Номер доступен?"
   - [Нет] → "Отображение ошибки" → стрелка возвращается к "Ввод дат"
   - [Да] → продолжение
4. "Создание бронирования"
5. "Расчет общей стоимости"

#### Шаг 9: Добавление процесса оплаты
Добавьте следующие активности:
1. "Инициация процесса оплаты"
2. "Создание Stripe Checkout Session"
3. "Перенаправление на Stripe"
4. "Ввод платежных данных"
5. "Обработка платежа"
6. Decision Node: "Оплата успешна?"
   - [Нет] → "Отображение ошибки оплаты" → стрелка к "Отображение списка бронирований" → End
   - [Да] → продолжение

#### Шаг 10: Завершающие активности
1. "Обновление статуса платежа (paid)"
2. "Обновление статуса бронирования (confirmed)"
3. "Отправка чека на email"
4. "Логирование в admin.log"
5. "Отображение страницы успеха"

#### Шаг 11: Добавление конечного узла
1. Выберите инструмент "Activity Final Node" (круг с точкой внутри)
2. Поместите его в конце потока
3. Соедините последнюю активность с конечным узлом

#### Шаг 12: Добавление Swimlanes (дорожек) - опционально
Для наглядности можно разделить диаграмму на дорожки по ролям:
1. Правый клик на диаграмме → Insert → Swimlane
2. Создайте дорожки:
   - "Пользователь" (User)
   - "Система" (System)
   - "Stripe API"
   - "Email Service"
3. Перетащите соответствующие активности в нужные дорожки:
   - Пользователь: поиск, выбор, ввод данных
   - Система: проверки, создание записей, обновление статусов
   - Stripe API: создание сессии, обработка платежа
   - Email Service: отправка писем

#### Шаг 13: Настройка внешнего вида
1. Выровняйте активности по вертикали
2. Убедитесь, что стрелки не пересекаются
3. Для Decision Node добавьте подписи на стрелках ([Да], [Нет])
4. Можно добавить цвета для разных типов активностей:
   - Правый клик на активности → Presentation Options → Fill Color

#### Шаг 14: Добавление примечаний (Notes) - опционально
Можно добавить комментарии для уточнений:
1. Выберите инструмент "Note"
2. Кликните рядом с активностью
3. Введите текст (например, "Использует Stripe API v3")
4. Соедините примечание с активностью пунктирной линией

#### Шаг 15: Добавление альтернативного потока "Отмена бронирования"

## Дополнительные рекомендации:

### Для диаграммы классов:
- Используйте разные цвета для разных типов классов (модели - синий, сервисы - зеленый)
- Группируйте связанные классы рядом
- Не забудьте указать типы атрибутов и возвращаемые типы методов
