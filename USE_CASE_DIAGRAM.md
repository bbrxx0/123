# Диаграмма случаев использования - StayFinder

## Актеры системы

1. **Гость** - незарегистрированный пользователь
2. **Клиент** - зарегистрированный пользователь
3. **Администратор** - пользователь с правами администратора
4. **Платежная система (Stripe)** - внешняя система
5. **Email-сервис (SMTP)** - внешняя система

---

## Список случаев использования

### Гость
1. Просмотр списка отелей
2. Поиск отелей (по названию/городу)
3. Просмотр деталей отеля
4. Просмотр информации о номерах
5. Регистрация в системе
6. Вход в систему

### Клиент
7. Бронирование номера
8. Просмотр своих бронирований
9. Отмена бронирования
10. Оплата бронирования
11. Подтверждение email
12. Выход из системы

### Администратор
13. Управление отелями (создание/редактирование/удаление)
14. Управление номерами
15. Управление пользователями
16. Просмотр всех бронирований
17. Изменение статуса бронирования
18. Просмотр логов системы

### Системные use cases
19. Проверка доступности номера
20. Отправка email-уведомлений
21. Обработка платежа через Stripe

## Пошаговая инструкция создания диаграммы в Visual Paradigm

### Шаг 1: Создание нового проекта
1. Запустить Visual Paradigm
2. File → New Project
3. Выбрать тип: **Unified Process**
4. Указать имя проекта: **StayFinder**
5. Нажать **Create**

### Шаг 2: Создание Use Case диаграммы
1. В меню: **Diagram → New**
2. Выбрать **UML Behavioral** → **Use Case Diagram**
3. Назвать диаграмму: **StayFinder System**
4. Нажать **OK**

### Шаг 3: Добавление актеров
1. На панели инструментов слева найти **Actor**
2. Кликнуть на Actor, затем кликнуть на диаграмму
3. Ввести имя актера: **Гость**
4. Повторить для актеров:
   - **Клиент** (разместить под Гостем)
   - **Администратор** (разместить под Клиентом)
   - **Платежная система** (справа)
   - **Email-сервис** (справа)

### Шаг 4: Создание связи наследования между актерами
1. На панели выбрать **Generalization** (стрелка)
2. Провести от **Клиент** к **Гость** (Клиент наследует возможности Гостя)
3. Провести от **Администратор** к **Клиент** (Администратор наследует возможности Клиента)

### Шаг 5: Создание границы системы
1. На панели выбрать **System Boundary**
2. Нарисовать прямоугольник в центре
3. Назвать: **StayFinder System**
4. Расположить актеров Гость, Клиент, Администратор - слева от границы
5. Расположить Платежная система и Email-сервис - справа от границы

### Шаг 6: Добавление use cases для Гостя
Внутри границы системы добавить овалы (Use Case):
1. Кликнуть **Use Case** на панели
2. Кликнуть внутри границы системы
3. Создать use cases:
   - **Просмотр отелей**
   - **Поиск отелей**
   - **Просмотр деталей отеля**
   - **Регистрация**
   - **Вход в систему**

### Шаг 7: Связывание актера Гость с use cases
1. Выбрать **Association** (простая линия) на панели
2. Провести линию от актера **Гость** к каждому его use case

### Шаг 8: Добавление use cases для Клиента
Добавить новые use cases:
- **Бронирование номера**
- **Просмотр бронирований**
- **Отмена бронирования**
- **Оплата бронирования**
- **Подтверждение email**

Связать актера **Клиент** с этими use cases

### Шаг 9: Добавление use cases для Администратора
Добавить use cases:
- **Управление отелями**
- **Управление номерами**
- **Управление пользователями**
- **Просмотр всех бронирований**
- **Изменение статуса бронирования**
- **Просмотр логов**

Связать актера **Администратор** с этими use cases

### Шаг 10: Добавление системных use cases
Добавить вспомогательные use cases:
- **Проверка доступности номера**
- **Отправка email**
- **Обработка платежа**

### Шаг 11: Связи <<include>> и <<extend>>

#### Связь <<include>> (обязательное включение):
1. Выбрать **Include** на панели
2. От **Бронирование номера** → к **Проверка доступности номера**
3. От **Оплата бронирования** → к **Обработка платежа**
4. От **Регистрация** → к **Отправка email**
5. От **Подтверждение email** → к **Отправка email**

#### Связь <<extend>> (опциональное расширение):
1. Выбрать **Extend** на панели
2. От **Оплата бронирования** → к **Бронирование номера** (опционально можно оплатить)

### Шаг 12: Связь с внешними системами
1. **Association** от **Обработка платежа** к актеру **Платежная система**
2. **Association** от **Отправка email** к актеру **Email-сервис**

### Шаг 13: Форматирование диаграммы
1. Выровнять элементы: меню **Format → Alignment**
2. Автоматически расположить: **Format → Auto Layout**
3. Изменить цвета: правый клик → **Presentation Options → Fill Color**
4. Рекомендуемые цвета:
   - Актеры: светло-голубой
   - Use cases обычных пользователей: светло-зеленый
   - Use cases администратора: светло-оранжевый
   - Системные use cases: светло-серый

### Шаг 14: Сохранение и экспорт
1. Сохранить проект: **File → Save**
2. Экспортировать как изображение:
   - **File → Export → Active Diagram as Image**
   - Выбрать формат: **PNG** или **SVG**
   - Выбрать качество: **High**
   - Нажать **OK**

## Краткая схема расположения элементов

```
          [Гость]
             ↓ (generalization)
         [Клиент]
             ↓ (generalization)
      [Администратор]

     ┌──────────────────────────────────────────────┐
     │          StayFinder System                    │
     │                                               │
     │  ○ Просмотр отелей        ○ Управление      │ ←→ [Платежная система]
     │  ○ Поиск отелей              отелями         │
     │  ○ Регистрация            ○ Управление      │
     │  ○ Вход                      номерами        │
     │  ○ Бронирование           ○ Просмотр логов  │
     │  ○ Оплата                                     │
     │  ○ Просмотр бронирований                     │ ←→ [Email-сервис]
     │                                               │
     │  ○ Проверка доступности (системный)          │
     │  ○ Отправка email (системный)                │
     │  ○ Обработка платежа (системный)             │
     └──────────────────────────────────────────────┘
```

## Советы

1. **Не перегружай диаграмму** - если слишком много use cases, раздели на несколько диаграмм (например, отдельно для администратора)
2. **Используй заметки (Notes)** - для пояснения сложных связей
3. **Группируй похожие use cases** - визуально располагай рядом
4. **Проверь связи** - каждый use case должен быть связан хотя бы с одним актером
5. **Включай только видимое поведение** - не добавляй технические детали реализации

---

## Типичные ошибки

❌ Не создавай use case для каждой кнопки в интерфейсе  
✅ Создавай use case для бизнес-функции

❌ Не используй глаголы как "нажать", "кликнуть"  
✅ Используй бизнес-термины: "Забронировать", "Оплатить"

❌ Не добавляй технические детали (API, база данных)  
✅ Описывай функциональность с точки зрения пользователя
